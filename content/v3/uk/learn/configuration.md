# Конфігурація

## Огляд

Flight забезпечує простий спосіб налаштувати різні аспекти фреймворку відповідно до потреб вашого застосунку. Деякі параметри встановлено за замовчуванням, але ви можете змінити їх за потреби. Ви також можете встановлювати власні змінні для використання в усьому застосунку.

Чітка, багаторівнева конфігурація (типові значення у файлах + секрети середовища) також допомагає [інструментам ШІ-кодування](/learn/ai): агенти дізнаються, що для літералів є одне місце, а для секретів — інше, замість того щоб вигадувати читання `$_ENV` всередині контролерів.

## Розуміння

Ви можете налаштувати певну поведінку Flight, задавши значення конфігурації
через метод `set`.

```php
Flight::set('flight.log_errors', true);
```

У структурованому застосунку (включаючи [скелет](https://github.com/flightphp/skeleton)) ви зазвичай завантажуєте налаштування проєкту з `app/config/config.php`, а потім застосовуєте відповідні ключі до Engine (наприклад, `flight.base_url`, `flight.views.path`). Ви також можете ін’єктувати невеликий об’єкт конфігурації в контролери замість читання глобальних змінних усюди — це зручніше для тестів і для агентів, які дотримуються `AGENTS.md`.

## Базове використання

### Параметри конфігурації Flight

Нижче наведено список усіх доступних параметрів конфігурації:

- **flight.base_url** `?string` - Перевизначає базову URL-адресу запиту, якщо Flight працює в підкаталозі. (типово: null)
- **flight.case_sensitive** `bool` - Зіставлення URL-адрес із урахуванням регістру. (типово: false)
- **flight.handle_errors** `bool` - Дозволити Flight обробляти всі помилки внутрішньо. (типово: true)
  - Якщо ви хочете, щоб Flight обробляв помилки замість стандартної поведінки PHP, це має бути true.
  - Якщо у вас встановлено [Tracy](/awesome-plugins/tracy), вам потрібно встановити це значення false, щоб Tracy міг обробляти помилки.
  - Якщо у вас встановлено плагін [APM](/awesome-plugins/apm), вам потрібно встановити це значення true, щоб APM міг реєструвати помилки.
- **flight.log_errors** `bool` - Записувати помилки у файл журналу помилок вебсервера. (типово: false)
  - Якщо у вас встановлено [Tracy](/awesome-plugins/tracy), Tracy записуватиме помилки відповідно до конфігурацій Tracy, а не цієї конфігурації.
- **flight.debug** `bool` - Виводити детальну інформацію про помилку (повідомлення винятку, код і трасування стека) у браузері, коли виникає помилка. (типово: false)
  - **Ніколи не вмикайте це в продакшені** — це розкриває внутрішні деталі застосунку. Використовуйте це лише для локальної розробки або проміжного середовища.
  - Коли `false`, натомість показується загальне `500 Internal Server Error`. Поєднуйте з `flight.log_errors`, щоб фіксувати помилки на сервері.
- **flight.allow_method_override** `bool` - Дозволити перевизначення HTTP-методу через заголовок запиту `X-HTTP-Method-Override` або поле `_method` у тілі POST. (типово: true)
  - **Рекомендовано встановити це значення `false`** для застосунків, яким не потрібне підмінювання методів на основі HTML-форм, оскільки це не дає клієнтам підробляти запити `DELETE` або `PUT` через стандартну POST-форму.
  - Дивіться [Безпека](/learn/security#flight-configuration-hardening) для детальнішої інформації.
- **flight.views.path** `string` - Каталог, що містить файли шаблонів представлень. (типово: ./views)
- **flight.views.extension** `string` - Розширення файлів шаблонів представлень. (типово: `.php`; офіційний скелет встановлює його на `.twig` під час використання Twig)
- **flight.views.restrict_to_path** `bool` - Коли `true`, вбудований `View` Flight приймає лише файли шаблонів, які розв’язуються всередині `flight.views.path`. (типово: `false`). **Увімкніть це** для застосунків, які використовують вбудовані представлення. Дивіться [Безпека](/learn/security#flightviewsrestrict_to_path).
- **flight.content_length** `bool` - Встановити заголовок `Content-Length`. (типово: true)
  - Якщо ви використовуєте [Tracy](/awesome-plugins/tracy), це потрібно встановити на false, щоб Tracy міг правильно рендерити.
- **flight.v2.output_buffering** `bool` - Використовувати застаріле буферизування виводу. Дивіться [перехід на v3](migrating-to-v3). (типово: false)

### Конфігурація завантажувача

Додатково є ще одне налаштування конфігурації для завантажувача. Воно дозволить вам
автоматично завантажувати класи з `_` у назві класу.

```php
// Увімкнути завантаження класів із підкресленнями
// Типово true
Loader::$v2ClassLoading = false;
```

Пам’ятайте, що [автозавантаження](/learn/autoloading) також залежить від **регістру папок**, що відповідає вашим просторам імен — особливо з макетом `App\` + `app/Controller/` у скелеті.

### Конфігурація проєкту та `.env` (шаблон скелета)

Ядро Flight не вимагає файлів `.env`. Багато застосунків використовують лише PHP-масив конфігурації. Офіційний скелет розшаровує конфігурацію так, щоб секрети залишалися поза git, а Runway все одно міг безпечно переписувати **літеральну** конфігурацію:

1. **`.env` / реальне середовище** — секрети та перевизначення для розгортання (ігнорується git).
2. **`app/config/config.php`** — літеральні типові значення у вигляді PHP-масиву (скопійовані з `config_sample.php`). Бажано **без** виразів `$_ENV[...]` у цьому файлі: такі інструменти, як `runway config:set`, можуть переписати його як статичні значення й вбудувати секрети у файл.
3. **Об’єднання під час bootstrap** — середовище має пріоритет для зіставлених ключів; код застосунку читає об’єкт конфігурації або `$app->get()`, а не `$_ENV` у контролерах.

Приклад структури `config_sample.php` / `config.php` (спрощено):

```php
<?php
// Лише літерали — секрети належать .env для робочого процесу зі скелетом
return [
	'app' => [
		'env' => 'development',
		'debug' => true,
		'base_url' => '/',
		'timezone' => 'UTC',
	],
	'database' => [
		'driver' => 'sqlite', // або mysql, або '' для вимкнення
		'host' => 'localhost',
		'dbname' => '',
		'user' => '',
		'password' => '',
		'file_path' => __DIR__ . '/../../database.sqlite',
	],
	// ...
];
```

```bash
# .env.example → .env (скелет)
APP_ENV=development
APP_DEBUG=true
FLIGHT_BASE_URL=/
DB_DRIVER=sqlite
# DB_PASSWORD=...
```

Цей поділ зроблено навмисно для [проєктів, дружніх до ШІ](/learn/ai): інструкції можуть казати «типові значення в `config.php`, секрети в `.env`, ін’єктуйте Config / Engine — ніколи не вигадуйте доступ до середовища в контролері». Наявні застосунки можуть повністю ігнорувати `.env` і зберігати один файл конфігурації.

### Змінні

Flight дозволяє зберігати змінні, щоб їх можна було використовувати будь-де у вашому застосунку.

```php
// Зберегти вашу змінну
Flight::set('id', 123);

// Деінде у вашому застосунку
$id = Flight::get('id');
```
Щоб перевірити, чи змінну встановлено, можна зробити так:

```php
if (Flight::has('id')) {
  // Щось зробити
}
```

Ви можете очистити змінну так:

```php
// Очищає змінну id
Flight::clear('id');

// Очищає всі змінні
Flight::clear();
```

> **Примітка:** Те, що ви можете встановити змінну, не означає, що ви повинні це робити. Використовуйте цю функцію помірно. Причина в тому, що все збережене тут стає глобальною змінною. Глобальні змінні — це погано, бо їх можна змінити будь-де у вашому застосунку, що ускладнює пошук помилок. Крім того, це може ускладнити такі речі, як [модульне тестування](/guides/unit-testing). Надавайте перевагу ін’єкції через конструктор (як у скелеті + налаштуванні Dice) для сервісів і конфігурації, потрібних контролерам.

### Помилки та винятки

Усі помилки та винятки перехоплюються Flight і передаються методу `error`,
якщо `flight.handle_errors` встановлено на true.

Стандартна поведінка — надіслати загальну відповідь `HTTP 500 Internal Server Error`
разом із деякою інформацією про помилку.

Ви можете [перевизначити](/learn/extending) цю поведінку відповідно до своїх потреб:

```php
Flight::map('error', function (Throwable $error) {
  // Обробити помилку
  echo $error->getTraceAsString();
});
```

За замовчуванням помилки не записуються на вебсервері. Ви можете увімкнути це,
змінивши конфігурацію:

```php
Flight::set('flight.log_errors', true);
```

#### 404 Не знайдено

Коли URL-адресу не вдається знайти, Flight викликає метод `notFound`. Стандартна
поведінка — надіслати відповідь `HTTP 404 Not Found` із простим повідомленням.

Ви можете [перевизначити](/learn/extending) цю поведінку відповідно до своїх потреб:

```php
Flight::map('notFound', function () {
  // Обробити не знайдено
});
```

## Усунення несправностей
- Якщо у вас виникають проблеми з визначенням усіх значень вашої конфігурації, ви можете виконати `var_dump(Flight::get());`
- Якщо Runway або інструменти розгортання переписали `config.php`, переконайтеся, що секрети не було закомічено — зберігайте їх у `.env` або реальному середовищі, коли використовуєте шаблон скелета.
