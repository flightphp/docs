# Конфигурация

## Обзор

Flight предоставляет простой способ настроить различные аспекты фреймворка под нужды вашего приложения. Некоторые параметры установлены по умолчанию, но вы можете переопределить их по мере необходимости. Вы также можете задавать собственные переменные для использования во всем приложении.

Четкая многослойная конфигурация (файловые значения по умолчанию + секреты окружения) также помогает [AI-инструментам для кодирования](/learn/ai): агенты узнают, где находятся литералы и где секреты, вместо того чтобы изобретать чтение `$_ENV` внутри контроллеров.

## Понимание

Вы можете настроить определенное поведение Flight, задавая значения конфигурации через метод `set`.

```php
Flight::set('flight.log_errors', true);
```

В структурированном приложении (включая [скелет](https://github.com/flightphp/skeleton)) вы обычно загружаете настройки проекта из `app/config/config.php`, а затем применяете соответствующие ключи к Engine (например, `flight.base_url`, `flight.views.path`). Вы также можете внедрить небольшой объект конфигурации в контроллеры вместо чтения глобальных переменных повсюду — это удобнее для тестов и для агентов, следующих `AGENTS.md`.

## Базовое использование

### Параметры конфигурации Flight

Ниже приведен список всех доступных параметров конфигурации:

- **flight.base_url** `?string` — Переопределяет базовый URL запроса, если Flight работает в подкаталоге. (по умолчанию: null)
- **flight.case_sensitive** `bool` — Учитывать регистр при сопоставлении URL. (по умолчанию: false)
- **flight.handle_errors** `bool` — Разрешить Flight обрабатывать все ошибки внутренне. (по умолчанию: true)
  - Если вы хотите, чтобы Flight обрабатывал ошибки вместо стандартного поведения PHP, это должно быть true.
  - Если у вас установлен [Tracy](/awesome-plugins/tracy), установите значение false, чтобы Tracy мог обрабатывать ошибки.
  - Если у вас установлен плагин [APM](/awesome-plugins/apm), установите значение true, чтобы APM мог логировать ошибки.
- **flight.log_errors** `bool` — Записывать ошибки в журнал ошибок веб-сервера. (по умолчанию: false)
  - Если у вас установлен [Tracy](/awesome-plugins/tracy), Tracy будет логировать ошибки на основе своих конфигураций, а не этой.
- **flight.debug** `bool` — Выводить подробную информацию об ошибке (сообщение исключения, код и трассировку стека) в браузере при возникновении ошибки. (по умолчанию: false)
  - **Никогда не включайте это в производственной среде** — это раскрывает внутренние детали приложения. Используйте только для локальной разработки или промежуточного стенда.
  - При значении `false` вместо этого показывается общий ответ `500 Internal Server Error`. Используйте вместе с `flight.log_errors` для сбора ошибок на стороне сервера.
- **flight.allow_method_override** `bool` — Разрешает переопределение HTTP-метода через заголовок запроса `X-HTTP-Method-Override` или поле `_method` в теле POST. (по умолчанию: true)
  - **Рекомендуется установить `false`** для приложений, которым не нужна подмена методов на основе HTML-форм, поскольку это предотвращает подделку клиентами запросов `DELETE` или `PUT` через стандартную POST-форму.
  - Подробнее см. [Безопасность](/learn/security#flight-configuration-hardening).
- **flight.views.path** `string` — Каталог, содержащий файлы шаблонов представлений. (по умолчанию: ./views)
- **flight.views.extension** `string` — Расширение файла шаблона представления. (по умолчанию: `.php`; официальный скелет устанавливает `.twig` при использовании Twig)
- **flight.views.restrict_to_path** `bool` — Когда `true`, встроенный `View` во Flight принимает только файлы шаблонов, которые разрешаются внутри `flight.views.path`. (по умолчанию: `false`). **Включите это** для приложений, использующих встроенные представления. См. [Безопасность](/learn/security#flightviewsrestrict_to_path).
- **flight.content_length** `bool` — Устанавливать заголовок `Content-Length`. (по умолчанию: true)
  - Если вы используете [Tracy](/awesome-plugins/tracy), установите значение false, чтобы Tracy мог корректно отображать содержимое.
- **flight.v2.output_buffering** `bool` — Использовать устаревшую буферизацию вывода. См. [миграцию на v3](migrating-to-v3). (по умолчанию: false)

### Конфигурация загрузчика

Существует также дополнительный параметр конфигурации для загрузчика. Он позволяет автоматически загружать классы с символом `_` в имени класса.

```php
// Включить загрузку классов с подчеркиванием
// По умолчанию: true
Loader::$v2ClassLoading = false;
```

Помните, что [автозагрузка](/learn/autoloading) также зависит от **регистра папок**, соответствующего вашим пространствам имен — особенно с раскладкой `App\` + `app/Controller/` из скелета.

### Конфигурация проекта и `.env` (шаблон скелета)

Ядро Flight не требует файлов `.env`. Многие приложения используют только PHP-массив конфигурации. Официальный скелет организует конфигурацию так, чтобы секреты не попадали в git, а Runway при этом мог безопасно перезаписывать **литеральную** конфигурацию:

1. **`.env` / реальное окружение** — секреты и переопределения для развертывания (в `.gitignore`).
2. **`app/config/config.php`** — литеральный PHP-массив значений по умолчанию (копия из `config_sample.php`). Предпочтительно **не** использовать выражения `$_ENV[...]` внутри этого файла: такие инструменты, как `runway config:set`, могут перезаписать его статическими значениями и случайно сохранить секреты в файле.
3. **Объединение при загрузке** — для сопоставленных ключей приоритет у окружения; код приложения читает объект конфигурации или `$app->get()`, а не `$_ENV` в контроллерах.

Пример структуры `config_sample.php` / `config.php` (упрощенно):

```php
<?php
// Только литералы — секреты принадлежат .env для рабочего процесса скелета
return [
	'app' => [
		'env' => 'development',
		'debug' => true,
		'base_url' => '/',
		'timezone' => 'UTC',
	],
	'database' => [
		'driver' => 'sqlite', // или mysql, или '' для отключения
		'host' => 'localhost',
		'dbname' => '',
		'user' => '',
		'password' => '',
		'file_path' => __DIR__ . '/../../database.sqlite',
	],
	// ...
];
```

```bash
# .env.example → .env (скелет)
APP_ENV=development
APP_DEBUG=true
FLIGHT_BASE_URL=/
DB_DRIVER=sqlite
# DB_PASSWORD=...
```

Это разделение намеренно для [AI-дружелюбных проектов](/learn/ai): инструкции могут гласить: «значения по умолчанию в `config.php`, секреты в `.env`, внедряйте Config / Engine — никогда не изобретайте доступ к окружению в контроллере». Существующие приложения могут полностью игнорировать `.env` и использовать один файл конфигурации.

### Переменные

Flight позволяет сохранять переменные, чтобы их можно было использовать в любом месте вашего приложения.

```php
// Сохраняем переменную
Flight::set('id', 123);

// В другом месте приложения
$id = Flight::get('id');
```

Чтобы проверить, была ли установлена переменная, вы можете сделать:

```php
if (Flight::has('id')) {
  // Что-то сделать
}
```

Вы можете очистить переменную следующим образом:

```php
// Очищает переменную id
Flight::clear('id');

// Очищает все переменные
Flight::clear();
```

> **Примечание:** Возможность установить переменную не означает, что вы должны это делать. Используйте эту функцию умеренно. Причина в том, что все, что хранится здесь, становится глобальной переменной. Глобальные переменные плохи, потому что они могут быть изменены из любого места в вашем приложении, что затрудняет отслеживание ошибок. Кроме того, это может усложнить такие вещи, как [модульное тестирование](/guides/unit-testing). Предпочитайте внедрение через конструктор (как в скелете с настройкой Dice) для сервисов и конфигурации, которые нужны контроллерам.

### Ошибки и исключения

Все ошибки и исключения перехватываются Flight и передаются в метод `error`, если `flight.handle_errors` установлен в true.

Поведение по умолчанию — отправить общий ответ `HTTP 500 Internal Server Error` с некоторой информацией об ошибке.

Вы можете [переопределить](/learn/extending) это поведение для своих нужд:

```php
Flight::map('error', function (Throwable $error) {
  // Обработка ошибки
  echo $error->getTraceAsString();
});
```

По умолчанию ошибки не записываются в журнал веб-сервера. Вы можете включить это, изменив конфигурацию:

```php
Flight::set('flight.log_errors', true);
```

#### 404 Не найдено

Когда URL не найден, Flight вызывает метод `notFound`. Поведение по умолчанию — отправить ответ `HTTP 404 Not Found` с простым сообщением.

Вы можете [переопределить](/learn/extending) это поведение для своих нужд:

```php
Flight::map('notFound', function () {
  // Обработка случая "не найдено"
});
```

## Устранение неполадок
- Если у вас возникают проблемы с определением всех значений вашей конфигурации, вы можете выполнить `var_dump(Flight::get());`
- Если Runway или инструменты развертывания перезаписали `config.php`, убедитесь, что секреты не были закоммичены — храните их в `.env` или в реальном окружении при использовании шаблона скелета.
