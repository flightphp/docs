# Конфигурация

## Обзор

Flight предоставляет простой способ настройки различных аспектов фреймворка под нужды вашего приложения. Некоторые параметры заданы по умолчанию, но вы можете переопределить их при необходимости. Вы также можете задавать собственные переменные для использования по всему приложению.

Чёткая, многоуровневая конфигурация (значения по умолчанию в файлах + секреты окружения) также помогает [инструментам для ИИ-кодинга](/learn/ai): агенты узнают, что есть одно место для литералов и одно место для секретов, вместо того чтобы изобретать чтение `$_ENV` внутри контроллеров.

## Понимание

Вы можете настроить определённое поведение Flight, задавая значения конфигурации
через метод `set`.

```php
Flight::set('flight.log_errors', true);
```

В структурированном приложении (включая [skeleton](https://github.com/flightphp/skeleton)) вы обычно загружаете настройки проекта из `app/config/config.php`, а затем применяете соответствующие ключи к Engine (например, `flight.base_url`, `flight.views.path`). Вы также можете внедрять небольшой объект конфигурации в контроллеры вместо повсеместного чтения глобальных переменных — это удобнее для тестов и для агентов, следующих `AGENTS.md`.

## Базовое использование

### Параметры конфигурации Flight

Ниже приведён список всех доступных параметров конфигурации:

- **flight.base_url** `?string` - Переопределяет базовый URL запроса, если Flight работает в подкаталоге. (по умолчанию: null)
- **flight.case_sensitive** `bool` - Учитывать регистр при сопоставлении URL. (по умолчанию: false)
- **flight.handle_errors** `bool` - Разрешить Flight обрабатывать все ошибки внутри. (по умолчанию: true)
  - Если вы хотите, чтобы Flight обрабатывал ошибки вместо стандартного поведения PHP, этот параметр должен быть true.
  - Если у вас установлен [Tracy](/awesome-plugins/tracy), вам нужно установить этот параметр в false, чтобы Tracy мог обрабатывать ошибки.
  - Если у вас установлен плагин [APM](/awesome-plugins/apm), вам нужно установить этот параметр в true, чтобы APM мог логировать ошибки.
- **flight.log_errors** `bool` - Записывать ошибки в файл журнала ошибок веб-сервера. (по умолчанию: false)
  - Если у вас установлен [Tracy](/awesome-plugins/tracy), Tracy будет логировать ошибки на основе конфигурации Tracy, а не этой конфигурации.
- **flight.debug** `bool` - Выводить подробную информацию об ошибке (сообщение исключения, код и трассировку стека) в браузере при возникновении ошибки. (по умолчанию: false)
  - **Никогда не включайте это в production** — это раскрывает внутренние детали приложения. Используйте только для локальной разработки или staging.
  - Когда `false`, вместо этого показывается общая ошибка `500 Internal Server Error`. Используйте вместе с `flight.log_errors`, чтобы фиксировать ошибки на стороне сервера.
- **flight.allow_method_override** `bool` - Разрешить переопределение HTTP-метода через заголовок запроса `X-HTTP-Method-Override` или поле `_method` в теле POST. (по умолчанию: true)
  - **Рекомендуется установить этот параметр в `false`** для приложений, которым не нужна подмена метода на основе HTML-форм, так как это предотвращает подделку клиентами запросов `DELETE` или `PUT` через стандартную POST-форму.
  - См. [Безопасность](/learn/security#flight-configuration-hardening) для получения дополнительной информации.
- **flight.views.path** `string` - Каталог, содержащий файлы шаблонов представлений. (по умолчанию: ./views)
- **flight.views.extension** `string` - Расширение файлов шаблонов представлений. (по умолчанию: `.php`; официальный skeleton устанавливает его в `.twig` при использовании Twig)
- **flight.views.restrict_to_path** `bool` - Когда `true`, встроенный `View` во Flight принимает только файлы шаблонов, которые разрешаются внутри `flight.views.path`. (по умолчанию: `false`). **Включите это** для приложений, использующих встроенные представления. См. [Безопасность](/learn/security#flightviewsrestrict_to_path).
- **flight.content_length** `bool` - Устанавливать заголовок `Content-Length`. (по умолчанию: true)
  - Если вы используете [Tracy](/awesome-plugins/tracy), этот параметр нужно установить в false, чтобы Tracy мог корректно отображаться.
- **flight.v2.output_buffering** `bool` - Использовать устаревшую буферизацию вывода. См. [миграция на v3](migrating-to-v3). (по умолчанию: false)

### Конфигурация загрузчика

Дополнительно есть ещё один параметр конфигурации для загрузчика. Он позволит вам
автоматически загружать классы с `_` в имени класса.

```php
// Включить загрузку классов с подчёркиваниями
// По умолчанию true
Loader::$v2ClassLoading = false;
```

Помните, что [автозагрузка](/learn/autoloading) также зависит от **регистра папок**, соответствующего вашим пространствам имён, — особенно в структуре `App\` + `app/Controller/` из skeleton.

### Конфигурация проекта и `.env` (шаблон skeleton)

Ядро Flight не требует файлов `.env`. Многие приложения используют только массив конфигурации PHP. Официальный skeleton использует многоуровневую конфигурацию, чтобы секреты не попадали в git, а Runway всё ещё мог безопасно перезаписывать **литеральную** конфигурацию:

1. **`.env` / реальное окружение** — секреты и переопределения для деплоя (игнорируется git).
2. **`app/config/config.php`** — литеральные значения по умолчанию в виде массива PHP (скопированные из `config_sample.php`). Предпочитайте **не** использовать выражения `$_ENV[...]` внутри этого файла: такие инструменты, как `runway config:set`, могут перезаписать его статическими значениями и зашить секреты в файл.
3. **Объединение при бутстрапе** — окружение имеет приоритет для сопоставленных ключей; код приложения читает объект конфигурации или `$app->get()`, а не `$_ENV` в контроллерах.

Пример структуры `config_sample.php` / `config.php` (упрощённо):

```php
<?php
// Только литералы — секреты должны быть в .env для рабочего процесса skeleton
return [
	'app' => [
		'env' => 'development',
		'debug' => true,
		'base_url' => '/',
		'timezone' => 'UTC',
	],
	'database' => [
		'driver' => 'sqlite', // или mysql, или '' чтобы отключить
		'host' => 'localhost',
		'dbname' => '',
		'user' => '',
		'password' => '',
		'file_path' => __DIR__ . '/../../database.sqlite',
	],
	// ...
];
```

```bash
# .env.example → .env (skeleton)
APP_ENV=development
APP_DEBUG=true
FLIGHT_BASE_URL=/
DB_DRIVER=sqlite
# DB_PASSWORD=...
```

Это разделение сделано намеренно для [дружественных к ИИ проектов](/learn/ai): инструкции могут гласить «значения по умолчанию в `config.php`, секреты в `.env`, внедряйте Config / Engine — никогда не изобретайте доступ к env в контроллере». Существующие приложения могут полностью игнорировать `.env` и хранить один файл конфигурации.

### Переменные

Flight позволяет сохранять переменные, чтобы их можно было использовать в любом месте приложения.

```php
// Сохраните вашу переменную
Flight::set('id', 123);

// В другом месте вашего приложения
$id = Flight::get('id');
```
Чтобы проверить, была ли установлена переменная, можно сделать:

```php
if (Flight::has('id')) {
  // Сделайте что-нибудь
}
```

Вы можете очистить переменную так:

```php
// Очищает переменную id
Flight::clear('id');

// Очищает все переменные
Flight::clear();
```

> **Примечание:** То, что вы можете задать переменную, не означает, что вы должны это делать. Используйте эту возможность умеренно. Причина в том, что всё, что здесь сохранено, становится глобальной переменной. Глобальные переменные плохи тем, что их можно изменить из любого места приложения, что затрудняет поиск ошибок. Кроме того, это может усложнить такие вещи, как [модульное тестирование](/guides/unit-testing). Предпочитайте внедрение через конструктор (как в связке skeleton + Dice) для сервисов и конфигурации, которые нужны контроллерам.

### Ошибки и исключения

Все ошибки и исключения перехватываются Flight и передаются методу `error`,
если `flight.handle_errors` установлен в true.

Поведение по умолчанию — отправлять общий ответ `HTTP 500 Internal Server Error`
с некоторой информацией об ошибке.

Вы можете [переопределить](/learn/extending) это поведение под свои нужды:

```php
Flight::map('error', function (Throwable $error) {
  // Обработать ошибку
  echo $error->getTraceAsString();
});
```

По умолчанию ошибки не логируются на веб-сервере. Вы можете включить это,
изменив конфигурацию:

```php
Flight::set('flight.log_errors', true);
```

#### 404 Not Found

Когда URL не найден, Flight вызывает метод `notFound`. Поведение по умолчанию —
отправить ответ `HTTP 404 Not Found` с простым сообщением.

Вы можете [переопределить](/learn/extending) это поведение под свои нужды:

```php
Flight::map('notFound', function () {
  // Обработать отсутствие страницы
});
```

## Устранение неполадок
- Если у вас возникают проблемы с определением всех значений вашей конфигурации, вы можете выполнить `var_dump(Flight::get());`
- Если Runway или инструменты деплоя перезаписали `config.php`, убедитесь, что секреты не были закоммичены — храните их в `.env` или реальном окружении при использовании шаблона skeleton.
